# Лог решений

Формат: дата и время (Asia/Bishkek, +06:00), решение, почему, какие варианты отвергли.

## 2026-10-19 11:30 — Выбрано задание 1 (Notetaker)
Решила Фени. Оценка с агентом: 10–14 часов активной работы. Срок поставили 4 дня с запасом.

## 2026-10-19 11:40 — Backend: Python + FastAPI
Python Фени знает по своему проекту и сможет объяснить код. FastAPI асинхронный (нужен WebSocket) и сам строит документацию API.
Отвергли: Node.js — один язык с фронтендом, но менее знаком; Go — дольше писать.

## 2026-10-19 11:40 — Вход: почта + пароль, cookie-сессия
Показывает изоляцию данных пользователей, не сложнее варианта без входа. Сессия в БД (а не JWT), чтобы выход работал сразу и тот же cookie авторизовал WebSocket. Плюс демо-аккаунт для проверяющих.
Отвергли: без входа (слабо выглядит), вход по ссылке из письма (дольше).

## 2026-10-19 11:50 — Отдельный процесс worker для напоминаний
Напоминания не должны зависеть от числа копий API и его перезапусков. Задания хранятся в БД (`reminder_jobs`), выбираются через `FOR UPDATE SKIP LOCKED` → два worker'а не отправят одно и то же.
Отвергли: APScheduler в процессе API (дубли при нескольких копиях, задания в памяти), Celery + Redis (лишние сервисы для такого объёма).

## 2026-10-19 11:50 — Синхронизация вкладок: WebSocket + Postgres LISTEN/NOTIFY
Postgres уже есть; NOTIFY в той же транзакции, что и изменение, — событие не уйдёт раньше коммита. Worker тоже может будить вкладки.
Отвергли: Redis pub/sub (лишний сервис), опрос раз в N секунд (задержка, нагрузка).

## 2026-10-19 11:55 — Конфликты: оптимистичная блокировка по `version`
Правка присылает версию, устаревшая → 409 с текущей версией. В открытом редакторе баннер появляется ещё до сохранения — по событию WebSocket.
Отвергли: «последний победил» (правка теряется молча — прямо запрещено заданием), блокировка заметки на время редактирования (зависает при закрытой вкладке).

## 2026-10-19 12:00 — Повторы: своя развёртка в поясе серии, 31-е → последний день месяца
Три типа повторов проще написать и протестировать самим, чем подстраиваться под `dateutil.rrule`, который пропускает короткие месяцы. Пояс серии хранится в заметке, чтобы «в 9:00» оставалось 9:00 при переходе на летнее время и при смене пояса в настройках момент не сдвигался.

## 2026-10-19 12:00 — Исключения отдельной таблицей, «начиная с этого дня» = разрез серии
Вхождение = (note_id, исходное время). Правка одного — строка-исключение. «Начиная с этого дня» закрывает старую серию датой окончания и создаёт новую: прошлые вхождения физически не меняются.

## 2026-10-19 12:05 — Напоминания, пропущенные во время простоя
Событие ещё впереди → отправить сразу с пометкой «с опозданием». Событие уже прошло → не слать письмо (бесполезно), отметить `skipped`, показать во вкладке одно сводное уведомление.

## 2026-10-19 12:05 — Письма: transactional outbox + Message-ID
Запись в outbox — в той же транзакции, что и отметка «напоминание сработало». Остаточный риск дубля (падение между SMTP-отправкой и записью статуса) закрываем заголовком Message-ID = id задания и честно описываем.

## 2026-10-19 12:10 — Frontend: React + TS + Mantine + FullCalendar + TanStack Query/Virtual
FullCalendar даёт три вида и перетаскивание (MIT-плагины), с Luxon — показ в нужном поясе. Mantine — готовые формы, выбор даты и цвета, всплывающие уведомления. TanStack Query + события WS = все экраны обновляются одним механизмом. Virtual — тысячи строк без тормозов.
Отвергли: Vue (React популярнее, больше готовых компонентов календаря), свой календарь (день работы минимум).

## 2026-10-19 12:10 — Почта: Mailpit
Ловит SMTP, показывает письма в браузере и имеет API — удобно доказывать «ровно одно письмо» в тестах.

## 2026-10-19 15:10 — Python 3.12 вместо 3.13
Интернет ~0,4 МБ/с: 3.12 уже установлен (uv), 3.13 пришлось бы качать. Все библиотеки проекта поддерживают 3.12, разницы для задания нет.

## 2026-10-19 15:15 — Схема БД через Alembic, тесты — на отдельной базе `notetaker_test`
Схема создаётся только миграциями (тесты тоже накатывают миграцию, а не `create_all`) — так проверяется именно то, что поедет к проверяющим. `alembic check` подтверждает, что модели и миграция совпадают. Отдельная база создаётся init-скриптом Postgres: тесты не трогают рабочие данные; каждый тест в транзакции с откатом.

## 2026-10-19 15:15 — Ограничения в самой базе
Уникальность тегов без учёта регистра, цвет `#RRGGBB`, напоминания только 10/60/1440 минут, `until` только у повторов, одно исключение на вхождение, уникальный ключ задания напоминания и `idempotency_key` письма. Даже ошибка в коде не запишет неверные данные и не создаст дубль письма.
