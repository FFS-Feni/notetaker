# Notetaker

[![tests](https://github.com/FFS-Feni/notetaker/actions/workflows/tests.yml/badge.svg)](https://github.com/FFS-Feni/notetaker/actions/workflows/tests.yml)

Личные заметки, привязанные к дате и времени: календарь, теги, повторы, напоминания письмом и всплывающим уведомлением во всех открытых вкладках. Тестовое задание «Agentic Developer», задание 1.

- **Backend:** Python 3.12, FastAPI, SQLAlchemy 2 (async), PostgreSQL 17.
- **Фоновый процесс:** отдельный worker для напоминаний и писем.
- **Frontend:** React 19, TypeScript, Mantine, FullCalendar, TanStack Query.
- **Живые обновления:** WebSocket поверх PostgreSQL LISTEN/NOTIFY.
- **Почта:** заглушка Mailpit.

Наглядная карта устройства проекта: [docs/architecture-map.html](docs/architecture-map.html). Это схема с анимированными сценариями, все 40 пунктов задания с объяснением «как / зачем / чем доказано», макеты экранов и таблицы. Откройте файл в браузере. Карта составлена в день планирования (19.10): макеты экранов там ранние, актуальный интерфейс описан ниже в разделе «Интерфейс».

## Чем делали

**Claude Code** (расширение VS Code) с моделью **Claude Opus 5.5**. Агент работает прямо в проекте: пишет код, запускает Docker, миграции и тесты, смотрит скриншоты в браузере. Модель хорошо держит архитектуру и длинные многошаговые задачи. Человек ставил задачи, принимал решения и проверял результат.

**Вместо экспорта сессии** сдаём лог решений [docs/DECISIONS.md](docs/DECISIONS.md) (что выбрали, почему, что отвергли — с датой и временем) и журнал работы [docs/WORKLOG.md](docs/WORKLOG.md) (что и когда сделано). Сам экспорт не прикладываем: в сессии были личные данные, не относящиеся к проекту.

## Запуск

**Что нужно:** Docker 24+ с Compose v2 и свободные порты 5173, 8000, 5433, 8025, 1025. Для `make e2e` дополнительно нужен Node.js 20+, для `make test` — [uv](https://docs.astral.sh/uv/).

```bash
git clone <репозиторий> notetaker && cd notetaker
make up          # или: docker compose up -d --build --wait
```

| Адрес | Что там |
|---|---|
| http://localhost:5173 | приложение — кнопка «Войти в демо-аккаунт» (`demo@example.com` / `demo12345`) |
| http://localhost:8025 | Mailpit — все отправленные письма |
| http://localhost:8000/docs | документация API |

Если при сборке внутри Docker нет интернета (pip или npm не могут скачать пакеты), запустите так: `BUILD_NETWORK=host make up`.

Backend сам применяет миграции при старте и создаёт демо-аккаунт с примерами: повторы, теги, прошедшая заметка, заметка в корзине.

```bash
make demo   # заметка, напоминание о которой сработает через 30 секунд
make seed   # +5000 заметок в демо-аккаунт — проверить поиск и листание
make logs   # логи backend и worker
make down
```

### Windows 11, Linux, macOS

Приложение — это сайт, поэтому для работы нужен только браузер: Chrome, Edge, Firefox, Safari, в том числе на телефоне. Сервер запускается в Docker одинаково везде.

- **Linux / macOS:** `make up`.
- **Windows 11:** Docker Desktop (с WSL 2), затем в PowerShell из папки проекта:
  ```powershell
  docker compose up -d --build --wait
  docker compose exec backend python -m scripts.demo_reminder   # то же, что make demo
  ```
  Если при сборке внутри Docker нет интернета: `$env:BUILD_NETWORK="host"; docker compose up -d --build --wait`.

Что проверяется автоматически на GitHub (значок вверху):
- тесты backend;
- браузерные тесты в **Chrome, Firefox, WebKit (движок Safari)** и в эмуляции телефона;
- отдельный прогон на **Windows**: сборка фронтенда и логика повторов с часовыми поясами (в Windows нет встроенной базы поясов, её даёт пакет `tzdata`).

Переводы строк закреплены в `.gitattributes`, клон на Windows ничего не ломает.

## Проверить руками за 2 минуты

1. `make up`, откройте http://localhost:5173 в **двух вкладках** рядом и войдите в демо-аккаунт.
2. В первой вкладке измените заметку. Вторая обновится сама: календарь, список, «Ближайшее».
3. Откройте одну и ту же заметку в обеих вкладках. Во второй начните печатать, в первой сохраните. Во второй появится баннер «Заметку изменили в другой вкладке», ваш текст не пропадёт.
4. `make demo`. Через 30 секунд уведомление всплывёт в **обеих** вкладках, а в http://localhost:8025 придёт **одно** письмо. Нажмите F5: уведомление не появится снова.
5. Перетащите заметку в календаре на другой день. Повторяющаяся заметка перенесётся только в этот день, остальные дни останутся на месте.

## Интерфейс

| Вкладка | Что там |
|---|---|
| **Ближайшее** | «Фокус дня», «Сегодня», «Завтра», «На неделе», «Прошедшие». Переключателями вверху выбирается, какие блоки показывать; выбор хранится в настройках |
| **Календарь** | по умолчанию «2 недели» с крупными ячейками: текст задачи переносится, а не обрезается. Есть месяц, неделя, день, перетаскивание. Цвет — из палитры задачи |
| **Задачи** | слева «Неразобранные» (все активные задачи, поиск, фильтр по цвету), справа четыре блока: «Важные и срочные», «Важные, но несрочные», «Срочные, но неважные», «Неважные и несрочные». Перетаскивание из списка в блоки, между блоками и обратно. На карточке — цвет, ☆ в фокус дня, ✓ готово, меню «Переместить» (для телефона) |
| **Список** | все заметки, панель фильтров: поиск, теги, блок на доске, период, цвет (палитра), статус, порядок |
| **Цвета и теги** | 8 цветов задач, и что означает каждый, пишешь сам (по умолчанию «Горит», «Деньги», «Ждёт ответа», «Личное», «Здоровье», «Работа», «Учёба», «Прочее»). Теги — карточками со счётчиком заметок и кнопкой «Показать заметки» |
| **Корзина** | фильтры: поиск, теги, цвет, «когда удалена». У каждой заметки видно, где и когда она была: дата, блок на доске, фокус дня, повтор, когда удалена и через сколько дней исчезнет |

На всех вкладках:
- цвет задачи меняется в один клик по кружку на карточке;
- кнопка «Новая заметка» в шапке, клавиша **N**;
- светлая и тёмная тема, версия для телефона.

**Быстрый ввод одной строкой** — в шапке, на телефоне в «Ближайшем». Например, «завтра в 9 позвонить маме #семья !важно каждую неделю напомнить за час». Сервер разбирает строку, а пока печатаешь, видно, что понято:
- день: сегодня, завтра, в пятницу, 25.10, 1 ноября, через 2 часа;
- время: в 9, в 7 вечера, утром;
- повтор, напоминание;
- теги: существующие или новые, создаются сами;
- приоритет: !важно, !срочно, !!;
- цвет: *синий.

**«Напомнить позже» и «Готово» прямо во всплывающем напоминании.** Можно отложить на 10 минут, на час или до завтра 9:00. Нажал в одной вкладке — уведомление закрывается во всех. Отложенное напоминание переживает правку заметки, но снимается, если заметку отметили сделанной.

**Чек-листы в заметке.** Пункты с галочками, прогресс «2/5» на карточках во всех вкладках. Отметить пункт можно прямо с карточки, не открывая заметку.

**История изменений** — в редакторе заметки. Кто (имя из настроек), когда, откуда (например, «Chrome · Windows», «Safari · iPhone») и что изменил: «Заголовок: было → стало», цвет, время, теги, статус, правки отдельных вхождений повтора. Заметки остаются личными, как требует задание.

## Сверх задания: приоритеты и гибкие настройки

Методы, которые реально используют в работе, на заметках с датами:

- **Доска «Задачи» (матрица Эйзенхауэра).** Новая задача попадает в «Неразобранные». Оттуда её перетаскивают в один из блоков: «Важные и срочные», «Важные, но несрочные», «Срочные, но неважные», «Неважные и несрочные». На телефоне вместо перетаскивания — меню ⋯ «Переместить в». Отметки «Важно»/«Срочно» видны на карточках (❗ у важных), в списке есть фильтр по блоку.
- **Фокус дня** — методы «трёх главных дел» и Айви Ли. Звёздочкой выбираются главные дела на сегодня, они стоят сверху в «Ближайшем» с кнопкой «Готово». Лимит проверяет сервер, по умолчанию 3, в настройках от 1 до 6.
- **Гибкие настройки.** Хранятся на сервере и сразу применяются во всех вкладках.
  - Вкл/выкл: доска «Задачи», «Фокус дня», письма-напоминания (worker перестаёт их ставить в очередь, уведомления в интерфейсе остаются), всплывающие уведомления.
  - Тонкая настройка: лимит фокуса, напоминания по умолчанию для новой заметки, вид календаря при открытии, первый день недели, рабочие часы в неделе и дне, стартовая страница, тема.
  - Неверные значения сервер не примет (422).

Не стали добавлять:
- **GTD-«входящие» без даты** — у заметки по заданию всегда есть момент.
- **Kanban «в работе»** — путался бы со статусом «активна», от которого зависят напоминания.
- **Pomodoro** — это таймер, а не заметки.

Доказательства: [backend/tests/test_priorities.py](backend/tests/test_priorities.py), [backend/tests/test_settings_prefs.py](backend/tests/test_settings_prefs.py), [e2e/tests/priorities.spec.js](e2e/tests/priorities.spec.js) и [backend/tests/test_board.py](backend/tests/test_board.py): перетаскивание на доске видно во второй вкладке, лимит фокуса из настроек, выключенная функция пропадает во всех вкладках, цвета, история изменений, фильтры корзины.

## Как это устроено (коротко)

- **Напоминания.** Это задания в таблице `reminder_jobs`, по одному на напоминание об одном вхождении.
  - Любое изменение заметки в той же транзакции пересчитывает её задания. Создаются только задания со сроком в будущем, поэтому прошедшее не досылается.
  - Worker раз в секунду забирает созревшие задания через `FOR UPDATE SKIP LOCKED`. Затем в одной транзакции: письмо в очередь `email_outbox`, уведомление для вкладок, `NOTIFY`.
  - Дубль невозможен по трём причинам: уникальный ключ задания, `SKIP LOCKED` и уникальный ключ письма.
- **Вкладки.** `NOTIFY` внутри транзакции уходит только после COMMIT. API слушает канал и рассылает событие по WebSocket всем вкладкам пользователя, вкладка перезапрашивает видимые данные.
- **Конфликты.** У заметки есть номер версии, устаревшая правка получает 409 и свежую версию. Открытый редактор с несохранёнными правками показывает баннер ещё до сохранения.
- **Повторы.** Хранится правило, вхождения вычисляются по «настенному» времени пояса серии. Правка одного вхождения хранится как исключение, «начиная с этого дня» делит серию на две.
- **Время.** В базе всё в UTC, на экране — в поясе из настроек. Поэтому смена пояса не двигает момент напоминания.

Подробно: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), решения с датами: [docs/DECISIONS.md](docs/DECISIONS.md).

### Напоминания, пропущенные во время простоя

Задание, просроченное больше чем на минуту, считается пропущенным, пока сервер не работал.

- **Событие ещё впереди** (встреча в 16:00, «за час» должно было прийти в 15:00, сервер поднялся в 15:30): напоминание отправляется сразу с пометкой «с опозданием».
- **Событие уже прошло:** письмо не отправляется, потому что оно бесполезно. Задание получает статус `skipped`, а во вкладке появляется одно сводное уведомление «пропущено напоминаний: N».

## Состояние

**Работает всё, что перечислено в задании:**
- заметки, теги, корзина;
- повторы с исключениями и разрезом серии;
- напоминания: письма и всплывающие уведомления;
- календарь «месяц / неделя / день» с перетаскиванием;
- список с поиском, фильтрами и сортировками на сервере;
- «Ближайшее»;
- настройки;
- синхронизация вкладок и конфликты;
- часовые пояса;
- перезапуск и простой.

Статус каждого пункта — в [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md).

**Ограничения, о которых стоит знать:**
- **Письмо может уйти дважды в одном редком случае.** Если worker упадёт ровно между SMTP-отправкой и записью «отправлено», после перезапуска письмо уйдёт ещё раз. У письма постоянный `Message-ID`, почтовые клиенты склеят дубль, но строго «ровно одно» SMTP гарантировать не может.
- **Исключение вхождения видно только в пределах 31 дня от исходной даты.** Если вхождение перенесли дальше, в календаре оно покажется только при просмотре периода рядом с исходной датой.
- **«Прошедшие» (активные) в «Ближайшем» — только за последние 7 дней.** Иначе ежедневная серия за год заполнила бы экран.
- **Пояс повторяющейся серии фиксируется при создании.** «Каждый день в 9:00» остаётся 9:00 там, где серию создали. Смена пояса в настройках меняет только отображение. Так задумано.
- **Вход минимальный.** Почта не подтверждается, сброса пароля нет.
- **Frontend в Docker — готовая сборка, которую отдаёт `vite preview`** (он же проксирует `/api` и WebSocket). Для боевого развёртывания лучше nginx со сжатием и HTTPS.
- **Мобильная версия простая:** календарь открывается на виде «День», меню — по кнопке. Отдельного приложения или Web Push нет.
- **Тесты нужно запускать на запущенной базе.** e2e по умолчанию берёт системный Chromium (`/usr/bin/chromium`, путь задаётся переменной `CHROMIUM`), иначе — браузер Playwright.

**CI:** [.github/workflows/tests.yml](.github/workflows/tests.yml) — тесты backend и браузерные тесты на Docker-версии при каждом push. Заработает после первой загрузки на GitHub, до этого не проверен.

**Чего не делали:** повтор «по будням» и произвольные интервалы; вложения к заметкам.

## Скорость и стабильность (замеры)

- **API на 5000 заметках:** список, поиск, фильтры, календарь на месяц, «Ближайшее», доска задач — 2–15 мс.
- **Нагрузка, 40 одновременных запросов:** 321 запрос/с, медиана 113 мс, ошибок 0. Помогли пул из 20 соединений с базой и два процесса uvicorn.
- **Открытие страницы:** календарь с событиями за ~0,4 с, 12 запросов. Это готовая сборка, экраны грузятся по требованию.
- **Перезапуски при открытых вкладках:**
  - backend или worker — вкладки сами переподключаются;
  - база — события снова доходят через 4–5 с, а вкладки перезапрашивают данные;
  - пока база лежит, API отвечает понятным 503.
- **Простой worker'а вживую:** пришло одно письмо с пометкой «с опозданием» и реальным остатком времени.
- **Стабильность тестов:** браузерные тесты, каждый 3 раза подряд, — 15/15.
- **Отказоустойчивость, `make chaos`:**
  - условия: 25 клиентов 75 секунд пишут и читают, работают два worker'а; по очереди перезапускаются backend и база, оба worker'а убиваются `kill -9` и запускаются снова;
  - итог: **0 потерянных подтверждённых записей** из 1233, **12 из 12 напоминаний — ровно по одному письму**, недоступность после перезапуска backend — около 4 с, после перезапуска базы — около 2 с;
  - во время сбоев клиенты получают «нет связи» или понятный 503, ответов 500 нет. Первый прогон нашёл 25 ответов 500 на редких видах обрыва базы, это исправлено.
